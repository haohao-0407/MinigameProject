# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity 2022.3.62f3 turn-based tactical combat mini-game. The theme is 吸血鬼 (Vampires) vs
吸血鬼猎人团 (Vampire Hunters) — two factions fight on a NavMesh battlefield, one commanded by
the player and the other by AI. Gameplay code lives under `Assets/Scripts/` in `Vampire.*`
namespaces; most of the rest of `Assets/` is sample/scaffold content (`TerrainSampleAssets/`,
`TextMesh Pro/`, `Samples/`, `AllSkyFree/`, `TutorialInfo/`) or generated URP render settings.

## Working through Unity (unity-mcp)

Driven through the `unity-mcp` plugin, not a headless CLI. There is no `dotnet build`/`msbuild`
workflow — the Editor owns compilation. Use the `unity_*` MCP tools for everything:

- On the first tool call instances are auto-discovered. If more than one Unity Editor is
  running, ask the user which to use and call `unity_select_instance` before proceeding.
- After editing C#, the Editor recompiles automatically. Check results with
  `unity_get_compilation_errors` (survives console clears — prefer it over `unity_console_log`
  for compile issues).
- Run/inspect play mode with `unity_play_mode`; capture what the player sees with
  `unity_graphics_game_capture`.
- Prefer `unity_*` tools over editing scene/prefab/asset YAML by hand — GUIDs and fileIDs are
  fragile. Editing `.cs` files under `Assets/Scripts/` directly is fine.
- The `.csproj`/`.sln` files at the root are Unity-generated for IDE IntelliSense. Do not
  hand-edit them; they are regenerated by the Editor.

## Architecture

Two distinct code cultures live side by side — respect the one you're editing:

- **Gameplay code** (`Assets/Scripts/` under `Vampire.*` namespaces): well-structured,
  UTF-8 Chinese comments, `[SerializeField]` private fields, ScriptableObject-driven data.
- **UI + bootstrap code** (`Assets/Scripts/UI/`, plus `Core/GameManager.cs`,
  `Core/SceneLoader.cs`, `Audio/WwiseAudioManager.cs`): no namespaces, static singletons,
  and Chinese comments that are **mojibake** (GBK saved as if UTF-8, e.g. `ɨ�赽��`). When
  editing these files, leave existing garbled comments alone rather than "fixing" them blind,
  and write any new comments in ASCII or clean UTF-8. `GameManager`/`SceneLoader`/
  `WwiseAudioManager` are empty stubs — real logic hasn't landed yet.

### Combat / turn loop (the heart of the game)

- `Turns/TurnManager` is the single orchestrator. On `Start` it collects all `Unit`s, sorts
  them by `UnitType.speed` (先攻/initiative) descending, and drives turns one unit at a time.
  Units of `playerFaction` take input (left-click ground = move, left-click enemy =
  approach/attack, Space = end turn); all other factions run coroutine AI (`RunEnemyTurn`:
  approach nearest hostile, attack, auto-end). It also owns the movement-preview `LineRenderer`
  and the faction/selection highlight rings.
- `Units/Unit` (MonoBehaviour, requires `NavMeshAgent`) holds live state: `CurrentHealth`,
  `CurrentStamina`, faction, and movement/attack logic. **Stamina is the core resource**:
  movement distance is budgeted as `stamina / moveCostPerMeter`, paths are truncated to that
  budget (`TruncateToBudget`/`BuildTruncatedPath`), and stamina resets each turn in
  `OnTurnStart`. `TryGetMovementPreview` computes the same truncated path without spending it.
- `Units/UnitType` (ScriptableObject, `Create > Game > Unit Type`) is the per-unit-kind stat
  template. `Units/HeroUnitType` extends it with a title and a `SkillType[]`.
- `Combat/Damage` is a static formula holder (`max(1, attack - defense)`) shared by attacks
  and future skills — put new combat math here rather than inlining it.
- `Core/Faction` is the `Vampire`/`VampireHunter` enum. Faction ≠ controller: who is the
  player is decided by `TurnManager.playerFaction`, independent of team.

### Skills (data-defined, NOT yet wired into combat)

`Skills/SkillType` (SO base) → `ActiveSkill` (stamina cost + cooldown) and `PassiveEffect`
(hooks: `OnTurnStart`, `OnDamaged`). `HeroUnitType.skills` references them. These define the
shape only — nothing in `TurnManager`/`Unit` calls `Execute`/hooks yet. Wiring them into the
turn loop is expected future work.

### UI system

`UI/Core/UIWindow` is the abstract base (requires `CanvasGroup`; open/close by toggling
alpha + interactable + blocksRaycasts). Every panel subclasses it and declares a `UIPanelType`
and `UIWindowType` (Page / Popup / Overlay). `UI/Core/UIManager` is a singleton that discovers
all `UIWindow`s in the scene at `Start`, and routes `Open(panel)`: Pages go through a
back-stack (`OpenPage`/`Back`, one visible at a time), Popups/Overlays just open on top.
Concrete panels live in `UI/Menu/` (MainMenu, StageSelect, Settings) and `UI/BattleUI/`
(BattleHUD, Pause, Result).

### Camera & editor tooling

- `Camera/CameraController` (`Vampire.CameraControl`): free RTS-style camera — WASD pan,
  scroll to change height, right-drag to look.
- `Editor/BakeMountainToTerrain` (`Tools > Bake Mountain To Terrain`): bakes the cubes under
  `MAP/mountain` into a Unity Terrain heightmap so the terrain can be brush-edited afterward.

## Scenes

Real game scenes: `Assets/Scenes/SampleScene.unity` (the battle scene — units + NavMesh),
`Assets/Scenes/UIScenes/MainMenu.unity`, `Assets/Scenes/Levels/Stage Select.unity`. The many
scenes under `TextMesh Pro/`, `Samples/ProBuilder/`, and `AllSkyFree/` are third-party demos.

## Navigation

Click-to-move and AI pathing depend on baked NavMesh data
(`Assets/Scenes/SampleScene/NavMesh-NavMesh.asset`) and `com.unity.ai.navigation`. Terrain or
layout changes that affect walkable surfaces require re-baking the NavMesh, or units will fail
to path (`Unit.MoveTo` early-returns on invalid paths, so failures are silent).

## Render pipeline

Active pipeline is **URP** (`com.unity.render-pipelines.universal` 14.0.12) —
`ProjectSettings/GraphicsSettings.asset` points at a URP asset, and quality tiers live in
`Assets/Settings/` (`URP-Performant`, `URP-Balanced`, `URP-HighFidelity`, each with a matching
`-Renderer`). Author shaders/materials for URP. HDRP resources under `TerrainSampleAssets/`
come from the terrain sample and are not the active path.

## Tests

`com.unity.test-framework` is installed but no tests exist yet. Run tests via the Unity Test
Runner (Window > General > Test Runner) or the MCP menu-item tools — not via an external test CLI.
